# Decisions: the `ip` verbs through a unix control socket

Date: 2026-11-12. For `docs/plans/0008-ip-control-socket.md`. Supersedes the "directly on the
`--db` sqlite file" row of `docs/decisions/0006-serve-and-ip.md`; everything else in 0006 and
0007 (verbs, wording, exit codes, canonicalisation, the miss semantics) carries over unchanged.

| Topic | Decision | Why |
|---|---|---|
| Transport | `serve` also listens on a unix socket; `list`, `show`, `unblock`, `clear` issue requests there and never open the db file | Direct db writes made every management run a second sqlite writer, which is what forced the `RecordFailure` busy retry in 0006. Going through the server keeps exactly one writer, and it separates management authority from db content: today `ip unblock` needs write access to the whole db file, which also allows editing bins and files with plain SQL. The socket grants the management verbs without granting the db. |
| Socket path | Default derived from `--db`: the db path plus `.sock` (`sandbin.db` → `sandbin.db.sock`, `/data/sandbin.db` → `/data/sandbin.db.sock`). Both `serve` and the `ip` verbs take `--socket <path>` to override; `serve` also honours `SANDBIN_SOCKET`. | Deriving means every existing invocation — `serve --db f`, `ip unblock --db f <ip>` — keeps working and the two sides can never drift apart on defaults. The override exists for the case where the socket should live somewhere else, e.g. a tmpfs while the db lives on disk. |
| Authority | The socket file's filesystem permission. `serve` creates it 0600 and chmods after bind. | Same shape as the 0006 rule ("protecting that file is the control"), now over a narrower object: whoever can connect can manage blocks, and connecting grants nothing else. 0600 means the server's own user; share deliberately by relaxing the mode. |
| Protocol | HTTP over the unix socket with a small JSON API on a separate `http.ServeMux`: `GET /ip` (all rows, same array shape as `--json`), `GET /ip/{ip}` (one row), `DELETE /ip/{ip}` (unblock), `DELETE /ip` (clear). Text tables stay rendered client-side. | The repo already speaks HTTP and the row-to-json shape already exists, so this adds no new format. A separate mux on a separate listener keeps every control endpoint off the public TCP port by construction. `curl --unix-socket` can drive it for debugging. |
| Offline management | Gone. `ip` verbs require a live `serve`; a refused or missing socket is a readable error naming the socket path, exit 1. There is no db-file fallback. | A fallback would keep the second writer around, which is the thing being removed. Management without the server is what the old design was for; the new one trades it for a single writer and narrower authority, and the plan says so out loud. |
| Missing `--db` | The 0006 `openIPStore` warning and its file creation are deleted with `openIPStore`. `ip` verbs never create or open a db file. | The warning existed because a typo'd `--db` silently created an empty table. A verb that cannot open the db at all cannot have that failure. |
| Stale socket at startup | If something answers on the socket path, `serve` refuses to start naming it. If the path holds a socket nobody answers on, `serve` replaces it. If the path holds anything that is not a socket (regular file, symlink), `serve` refuses and leaves it alone. | Refusing on a live listener prevents a second server from stealing the management address of the first. Not deleting a non-socket file prevents serve from eating an operator's file. |
| Server side of arguments | The client canonicalises with `canonicalIP` before dialing (so every message an operator sees keeps its exact 0006/0007 wording); the server treats the `{ip}` path value as an opaque key for the parameterised query and answers 404 for a key that is not there. | One canonicalisation point keeps the CLI wording stable. A parameterised lookup on an opaque string is safe, and weird keys only exist if raw SQL put them there. |
| `RecordFailure` busy retry | Kept as is. | With the `ip` verbs no longer opening the db it has no in-repo trigger left, but an old binary or a stray sqlite client can still open the file, and the retry is three lines with a test. Removing it would make an old binary's management runs silently drop charges again. |
| Log line | `sandbin listening on <addr>` stays byte-identical; serve gains a second line `sandbin control socket on <path>`. | Plan 0006 proved that line byte-identical against the pre-split binary; scripts may key on it, so it does not change. |
