# Decisions: serving the sandbin-preview skill

Plan: `docs/plans/0012-serve-skill.md`. Settled points; do not revisit during implementation.

| Point | Decision |
|---|---|
| Canonical file | Exactly one copy: repo-root `skills/sandbin-preview/SKILL.md`, hand-written. The server embeds that same file — no duplicated copy anywhere. |
| Embedding | `go:embed` cannot reach above a package directory and rejects symlinks outright (proven by experiment: `cannot embed irregular file`). So a module-root file `skill.go` (`package sandbin`) carries `//go:embed skills/sandbin-preview/SKILL.md` → `var PreviewSkillMD string`; `cmd/sandbin` imports `github.com/yookoala/sandbin`. No new dependency — `embed` is stdlib. |
| Containerfile | The build stage gains exactly two COPY lines (`COPY skill.go ./`, `COPY skills ./skills`) before the build, because the build now needs the root package. Nothing else changes. |
| gofmt gate | CI's `gofmt -l cmd` misses the new root `skill.go`; the CI step becomes `gofmt -l .`. Local sweeps match. |
| Route | `GET /skills/sandbin-preview/SKILL.md` only — 200, `Content-Type: text/markdown; charset=utf-8`, body = the embedded file byte-for-byte. Every other method 405. Routed as a static branch beside `/healthz` and `/verify-key`, before `splitBinPath`; "skills" is not a hex hash so it can never name or shadow a bin, same reasoning as the other two. Nothing under `/skills/` is charged — a GET never charges and a 405 is answered before any auth. Other paths under `/skills/` fall through to the normal unknown-bin 404. |
| Skill id | `sandbin-preview` — the directory name and the URL tail mirror the OpenCode path `.opencode/skills/sandbin-preview/SKILL.md` (verified against opencode.ai/docs/skills: directory-form `SKILL.md`, frontmatter `name` + `description`, description required for the model to discover the skill). |
| SKILL.md shape | Frontmatter `name: Sandbin preview` + a one-line `description`; body sections: when to use; first-time setup in this directory (`sandbin-client init` non-interactive flags, `.sandbin.yaml`, precedence); uploading files (reused-bin behaviour, result lines); uploading a folder (`--archive`, where files land, the human-facing URL); stdin with `--name`; `--no-extract`; `--title`/`--description`/`--describe`; the caps (1 MiB body/entry, 1000 entries, 32 MiB unpacked) with the refusal wordings an agent will see. Around 60-80 lines, commands copy-pasteable as written. No URL of any real server baked into it. |
| Install snippet | One canonical snippet shape (host is the only thing to adapt): `mkdir -p .opencode/skills/sandbin-preview` then `curl -fsSL <server>/skills/sandbin-preview/SKILL.md -o .opencode/skills/sandbin-preview/SKILL.md`. Front page uses `https://this.host` like its existing examples; README uses `http://localhost:8080` like its existing examples. Global install (`~/.config/opencode/skills`) mentioned in README only, one line. |
| Front page | Gains one short paragraph and that snippet in a `<pre>` block. Page stays static: it still names no bin, address or key beyond the `this.host` placeholder convention already in use. |
| Freshness | A server test compares the served body byte-for-byte against the repo file read from disk (`../../skills/sandbin-preview/SKILL.md`), so the embed can never silently serve a stale fork of the skill. |
| Front page base URL (added after shipping) | The `https://this.host` placeholder in the page's examples is replaced per request: host = `X-Forwarded-Host` (rightmost entry, only from a socket `isLocalAddr` or `--trusted-proxies` allows) else `Host`; scheme = `https` for a TLS socket or a trusted socket's `X-Forwarded-Proto: https`, else `http` (a proxy hop to this server is plain HTTP, so this is how the page reads correctly behind Nginx). Anything failing `^([A-Za-z0-9][A-Za-z0-9.\-]*\|\[[0-9A-Fa-f:.]+\])(:[0-9]+)?$` falls back to the placeholder — the snippet is made to be pasted into a shell, so the regex, not HTML escaping, is the guard. |
| Installer one-liner (added after shipping) | `skills/sandbin-preview/install.sh` is a bash template embedded beside the skill (`InstallScript` in `skill.go`) and served at `GET /skills/sandbin-preview/install.sh` as `text/plain; charset=utf-8` with `__SANDBIN_BASE__` replaced by `frontBase(r)` — the same detection and 405-before-auth discipline as the skill route. Run as `curl -fsSL …/install.sh | bash`; extra arguments reach a piped script via `bash -s --`. Default install dir is `$HOME/.agents/skills` (an OpenCode global discovery path), the `sandbin-preview` subfolder is `mkdir -p`'d, and SKILL.md is fetched from the same BASE the script itself came from. |
| Installer arguments | Optional `-d`/`--dest SKILLS_DIR` overrides the skills folder (so `--dest .opencode/skills` for one project, `--dest "$HOME/.claude/skills"` for a specific agent); `-h`/`--help` prints usage and installs nothing; any other argument exits 1 with `unknown argument` before anything is written. Parsing is a plain `while`/`case` loop, not `getopts` (short-only) or external `getopt` (util-linux-only) — long flags with zero dependencies, identical behavior piped or as a file. `${2:?}` refuses a missing `--dest` value. |
| Skill as template (added after shipping) | `SKILL.md` itself is a `text/template`: the server parses both embedded files once at startup (`template.Must` — a broken template stops the server, not one request) and renders `{{.Base}}` with `frontBase(r)` per request, so every served copy — frontmatter description, every example URL, the installer's `BASE` — names the exact server the visitor reached. The `install.sh` `__SANDBIN_BASE__` token is replaced by the same `{{.Base}}` mechanism. Consequence accepted: the git copy carries raw tokens; skills are installed from a running server. The freshness test now compares against the repo file rendered through the same template. |
| Skill-hosted client binary (added after shipping) | The skill tells the agent to build the client into the skill folder — `GOBIN="$SKILL" go install github.com/yookoala/sandbin/cmd/sandbin-client@latest` — and to always invoke `"$SKILL/sandbin-client"` by full path, never a bare PATH binary. `$SKILL` is the skill's base directory, which OpenCode hands to the model when it loads a `SKILL.md` skill (opencode.ai/docs/skills: "Provides the skill's base directory"; "Paths written inside the skill are relative to the directory containing SKILL.md") — so it works for the default install and for any `--dest`. `@latest` resolves: the module is public on proxy.golang.org as `v0.1.0`, tagged at `d484c80` (live-proved: download, install into a skill dir via `GOBIN`, full init/upload/describe round trip with that binary). |
| Skill key wording (added after shipping) | The skill shows `init --url <base> --api-key your-key` and says `--api-key` may be left out only at an interactive terminal (the client prompts only when `isTerminal(stdin)`); a non-terminal run without a key stops with `no API key: pass --api-key, set SANDBIN_API_KEY or answer the init prompt` and writes nothing — the exact refusal, live-proved, as is `server rejected this API key` for a wrong key. |
